# AI-assisted development log

This project was developed with AI assistance. The record below describes the
steps given to the tools, the resulting work, and the human review applied at
each stage. It intentionally records the development process rather than a
verbatim export of iterative chat messages.

| Step | Instructions given | Result and human verification |
| --- | --- | --- |
| 1. Requirements | Analyze the project requirements, ask questions before implementation, and propose the smallest complete React + Go solution that satisfies every required and optional item. | The scope, API contract, assumptions, PRD, and local work slices were reviewed and explicitly approved before code was written. |
| 2. Guardrails | Define deterministic acceptance criteria for arithmetic, REST behavior, coverage, Docker, documentation, responsive UI, and real-browser behavior. Keep the project local and never publish or submit it. | The criteria were recorded in the repository verification contract and remained local-only. |
| 3. Backend | Implement an idiomatic stateless Go REST API using decimal strings, strict validation, stable JSON errors, all required operations, power, percentage, and square root. Add unit and HTTP tests. | The implementation was reviewed against the API contract and exercised by unit tests, vet, coverage, and a real endpoint smoke test. |
| 4. Frontend | Build a familiar, responsive calculator in React and TypeScript, inspired by the macOS calculator. Include keyboard input, chaining, repeated equals, validation, API error recovery, and accessible controls without adding landing-page content. | The UI was iteratively reviewed in real browsers at mobile, tablet, and desktop sizes. Unit tests cover the state and API behavior. |
| 5. Packaging | Add Docker support for the frontend and backend, health-aware startup, and frontend-to-API proxying. Document local and Docker setup. | The composed application was built and tested through its real HTTP boundary. |
| 6. Adversarial review | Compare the implementation with the DoD, challenge arithmetic edge cases, verify normal calculator semantics, inspect SOLID/YAGNI trade-offs, and reject evidence that used a mocked backend. | The review found and corrected tiny-number square roots, operator chaining, stale documentation, external font loading, and the mocked browser API. |
| 7. Final verification | Run formatting, unit tests, coverage, typechecking, builds, endpoint smoke, Docker smoke, documentation checks, and real-browser checks against the Go service. Require separate human visual approval. | Automated results are generated by `ak-verify`; human approval is intentionally not granted by the AI. |
